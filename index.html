Как читать эти макеты
localhost:3000/…
Строка сверху каждого макета — это не часть приложения, а условный «браузер»: в адресной строке — реальный маршрут (роут) этого экрана.
Как: Имя
Пилюля (pill — маленький скруглённый ярлычок) «Как: …» — от чьего лица показан экран. В приложении с ролевой моделью один и тот же экран выглядит по-разному для разных пользователей — важно, кто именно смотрит.
КнопкаРОЛЬ
Пунктирная рамка + синий тег у элемента — этот элемент виден/активен не всем ролям. Текст тега — какой роли он доступен (например, «MANAGER+/ADMIN» — знак «+» значит «эта роль и выше»: роли в проекте по возрастанию прав — VIEWER (наблюдатель) → MANAGER (менеджер) → OWNER (владелец)). Без рамки — элемент виден всем, у кого есть доступ к экрану вообще.
Note: текст
Блок с пунктирной рамкой под макетом — пояснение о состояниях, которые не показаны на самом макете (пустой список, ошибка, граничный случай) — что должно быть, когда это встретится.
👆 кликабельно
Курсор-«рука» и подчёркивание — по такому элементу можно кликнуть прямо в макете, чтобы перейти на связанный экран (как в реальном приложении). Всё остальное — статичная иллюстрация.

Карта переходов между экранами

Дизайн-система — «Amber Ledger»

Точные значения из web/src/styles/tokens.css — реальные CSS-переменные (design-токены — именованные значения стиля, которые переиспользуются во всех компонентах вместо «зашитых» чисел/цветов) приложения, не приближение. Имена вида --color-bg — это буквально то же самое имя, что в коде: их можно найти в DevTools браузера (вкладка Elements → Styles/Computed) при проверке реального приложения. Если в приложении цвет/размер не совпадает с указанным здесь — это расхождение, достойное багрепорта.

Кнопки — размеры и варианты

Четыре варианта по важности действия: Primary (основное/главное действие на экране, заметная заливка) → Secondary (второстепенное, с рамкой) → Ghost (призрачная — почти невидимая до наведения, для некритичных действий вроде «Изменить») → Danger (опасное действие — удаление, красная).

ВариантГде встречается в макетах (примеры)
Главное действие экрана — обычно одно на страницу: «Создать проект», «Создать задачу», «Добавить» (участника/пользователя), «Отправить» (комментарий), «Сохранить» (профиль). На экранах входа/регистрации это визуально тот же акцентный цвет, но своя кнопка на всю ширину — «Войти» / «Создать аккаунт».
Действие рядом с primary, но не главное: «Отмена» в модалках, «Редактировать» (проект), «Назад»/«Вперёд» в пагинации.
Некритичные, «тихие» действия — обычно в строке таблицы: «Изменить»/«Удалить» у задачи и участника, «Изменить»/«Удалить» у комментария, «Деактивировать»/«Активировать» пользователя (админка), «Выйти» в шапке.
Только необратимые/опасные действия, двумя разными способами: (1) отдельная модалка подтверждения с кнопкой «Удалить» — так устроено удаление проекта, участника, задачи; (2) кнопка меняет текст прямо на месте, без модалки — «Удалить» → «Точно удалить?» + «Отмена» — так устроено удаление метки и комментария. Кнопка «Сбросить БД» — тоже Danger, со своим двухшаговым подтверждением («Точно сбросить всё?»). Обычная (неопасная) кнопка «Удалить» в строке таблицы, до подтверждения — Ghost (см. выше).
