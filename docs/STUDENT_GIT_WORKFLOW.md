# Работа с Git в рамках курса

## 1. Как устроен репозиторий курса

Вы работаете с публичным репозиторием курса — отдельным от внутреннего репозитория
преподавателя, где ведётся основная разработка платформы. В репозитории курса нет
истории коммитов, инструкторских заметок или служебных данных — только рабочий код
и документация, актуальные на момент публикации.

## 2. Клонирование

Git здесь нужен только для того, чтобы получить код и позже подтянуть обновления —
никаких веток, коммитов и Pull Request от вас не потребуется. Репозиторий публичный,
поэтому **аккаунт на GitHub не нужен** ни для клонирования, ни для получения
обновлений, ни для сдачи баг-репортов (они отправляются файлом напрямую, см. раздел 4).

```bash
git clone https://github.com/annakrutykh/taskflow-qa-training-public.git
cd taskflow-qa-training-public
```

## 3. Получение обновлений от преподавателя

Если преподаватель опубликовал обновления (новое задание, исправление окружения):

```bash
git pull
```

Если у вас есть собственные незакоммиченные изменения в файлах проекта и `pull`
конфликтует — проще всего отменить свои правки (`git checkout -- .`) и применить их
заново вручную поверх обновлённой версии, либо спросить преподавателя. Для заметок и
экспериментов, которые жалко потерять, используйте отдельные файлы вне отслеживаемых
git'ом путей или просто храните их отдельно от репозитория.

## 4. Как сдавать найденные дефекты

Git для сдачи баг-репортов **не используется**. Оформите каждый найденный дефект
отдельным `.md`-файлом по шаблону из `docs/STUDENT_BUG_REPORTING.md` и отправьте файл
преподавателю напрямую (почта/мессенджер/форма — как договоритесь на курсе). Коммитить,
пушить или открывать Pull Request не нужно.
