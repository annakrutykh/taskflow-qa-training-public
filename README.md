# TaskFlow API — учебная площадка для QA Engineer

REST API для управления проектами и задачами (упрощённый аналог Jira). Используется как
рабочая среда курса подготовки QA-инженеров: реальный backend, PostgreSQL, REST API,
которые нужно тестировать так же, как в настоящей компании.

Эта инструкция рассчитана на то, что вы **никогда раньше не работали с Docker** — читайте
по порядку, ничего не пропускайте.

---

## 1. Что установить перед началом

| Программа | Зачем нужна | Ссылка |
|---|---|---|
| **Docker Desktop** | Запускает приложение и PostgreSQL в изолированных контейнерах — вам не придётся вручную ставить Python, PostgreSQL и их зависимости | https://www.docker.com/products/docker-desktop/ |
| **Git** | Скачивание кода проекта и работа с версиями | https://git-scm.com/downloads |
| **DBeaver Community** | Просмотр и редактирование данных в PostgreSQL через графический интерфейс | https://dbeaver.io/download/ |
| **PyCharm Community** | Редактор для чтения кода API и написания тестов | https://www.jetbrains.com/pycharm/download/ |

После установки Docker Desktop **запустите его и дождитесь**, пока иконка кита в трее/меню
не покажет, что Docker работает (запущен движок). Все команды `docker compose ...` ниже
работают только при запущенном Docker Desktop.

**На macOS Git отдельно ставить обычно не нужно.** При первом запуске команды `git` в
Терминале система сама предложит установить **Command Line Tools** — соглашайтесь,
установка займёт пару минут, отдельно с git-scm.com ничего скачивать не придётся. Если
Git уже был установлен раньше (например, вместе с Xcode) — команда просто сработает,
никакого попапа не будет. На **Windows** так не работает — Git туда не встроен, нужен
установщик по ссылке из таблицы выше (или через терминал — см. ниже).

**На Windows Git можно поставить сразу через терминал**, не заходя на git-scm.com.
Откройте **PowerShell от администратора** (`Win` → напечатать «PowerShell» → правой
кнопкой по **Windows PowerShell** → «Запуск от имени администратора» — важно именно
PowerShell, обычная «Командная строка» (cmd) эти команды не выполнит) и запустите:

```powershell
$asset = (Invoke-RestMethod "https://api.github.com/repos/git-for-windows/git/releases/latest").assets | Where-Object { $_.name -like "*64-bit.exe" }
Invoke-WebRequest -Uri $asset.browser_download_url -OutFile "$env:TEMP\git-installer.exe"
Start-Process "$env:TEMP\git-installer.exe" -ArgumentList "/VERYSILENT /NORESTART" -Wait
```

Команда сама находит актуальный релиз через GitHub API и ставит его тихо — надёжнее,
чем ссылки с зашитым номером версии (они устаревают) или `winget`, который на части
машин просто отсутствует. После установки закройте и заново откройте терминал, чтобы
обновился `PATH`.

> На Windows для обычной работы с Git (клонирование, переключение веток и т.д.) не важно,
> какой терминал открыт — «Командная строка» (cmd) и PowerShell годятся одинаково.
> Разница важна только для отдельных команд-фиксов в разделе 14 «Если что-то не
> работает», где явно указано, где нужен именно PowerShell.

Проверить, что Docker и Git установлены, можно в терминале (macOS — приложение
"Терминал", Windows — PowerShell):

```bash
docker --version
git --version
```

Если обе команды выводят номер версии, а не ошибку "command not found" — всё готово.

Тот же git clone, но кнопками, без единой команды в терминале:

   Control**).

скачает его напрямую по ссылке. Единственное условие — Git должен быть
уже установлен (раздел 1 выше), PyCharm сама его найдёт и никакой
дополнительной привязки не потребует.

## 5. Запуск проекта

В корневой папке проекта выполните — сразу в фоновом режиме, чтобы контейнеры не занимали
терминал:

```bash
docker compose up --build -d
```

Первый запуск может занять несколько минут — скачиваются образы PostgreSQL и Python,
собирается образ приложения. Так как контейнеры поднимаются в фоне, терминал сразу
вернёт приглашение — это нормально, не означает ошибку.

При первом запуске автоматически:
- поднимается PostgreSQL;
- накатываются миграции схемы БД (создаются таблицы);
- база данных заполняется тестовыми данными.

Проверить, что всё реально поднялось и API готово принимать запросы — в разделе 6 ниже.

## 6. Как проверить, что контейнеры поднялись

```bash
docker compose ps
```

Все сервисы (`api`, `db`, `redis`, `redis-commander`, `elasticsearch`, `kibana`) должны быть в статусе `Up`
(или `running`/`healthy`). `elasticsearch`/`kibana` стартуют дольше остальных — дайте им
1-2 минуты после запуска. Если что-то из них в статусе `Exit`/`Restarting` — смотрите логи:

```bash
docker compose logs -f api
```

(`Ctrl+C` — выйти из просмотра логов, сами контейнеры при этом не остановятся).

Быстрая проверка, что API действительно отвечает:

```bash
curl http://localhost:8000/health
```

Ожидаемый ответ — JSON со статусом `ok` (или аналогичным) и кодом `200`.

Все инструменты для работы с запущенным проектом — в одном разделе.

### Swagger UI — интерактивная документация API

Откройте в браузере:

```
http://localhost:8000/docs
```

Здесь можно посмотреть все ручки API, их параметры и коды ответов, а также отправлять
запросы прямо из браузера ("Try it out"). Дополнительно доступна raw-схема:

```
http://localhost:8000/openapi.json
```

### DBeaver — просмотр и редактирование данных в PostgreSQL

Параметры подключения:

| Параметр | Значение |
|---|---|
| Host | localhost |
| Port | 5432 |
| Database | taskflow |
| Username | taskflow |
| Password | taskflow |

Пошагово:

1. Откройте DBeaver.
2. **File → New → Database Connection** (или кнопка "New Database Connection" на панели).
3. Выберите **PostgreSQL** → Next.
4. Заполните поля Host/Port/Database/Username/Password из таблицы выше.
5. Нажмите **Test Connection...** — если DBeaver попросит скачать драйвер PostgreSQL,
   согласитесь (Download).
6. После успешной проверки ("Connected") нажмите **Finish**.

После подключения в дереве слева будут доступны таблицы: `users`, `projects`, `tasks`,
`project_members`, `comments`, `labels`, `task_labels`, `audit_log`.

### Kibana и Redis — необязательные инструменты

**Все инструменты в этом разделе не обязательны** — весь курс можно пройти
через Swagger, Postman и PostgreSQL. Ниже — как подключиться, если хотите
попробовать; учебные задания по каждому — в `docs/STUDENT_LOG_ANALYSIS.md`.

#### Kibana (поиск по логам)

```
http://localhost:5601
```

Пошагово:

1. Откройте ссылку выше — логин/пароль вводить не нужно, авторизация в
   Kibana отключена.
2. Слева откройте меню (☰) → **Discover**.
3. При первом заходе Kibana попросит создать **Data View**. В форме два
   разных поля, не перепутайте:
   - **Name** — произвольное название для себя, на поиск не влияет
     (например, просто `taskflow-logs`).
   - **Index pattern** — сюда вводите именно `taskflow-logs-*`, **со
     звёздочкой на конце** (это wildcard: без неё Kibana не найдёт индексы,
     в имени которых зашита дата).
4. **Timestamp field** — выберите `@timestamp`.
5. Нажмите **Save data view to Kibana** (или **Create data view**).

#### Redis Commander (просмотр ключей Redis в браузере)

```
http://localhost:8081
```

Пошагово:

1. Откройте ссылку выше.
2. Ничего вводить не нужно — подключение к Redis уже настроено в
   `docker-compose.yml`, слева сразу видно дерево ключей (пустое, пока не
   сгенерируете активность через API).

## 10. Остановка контейнеров

**Обязательно останавливайте контейнеры, когда закончили работать** — пока они
запущены, Docker продолжает расходовать процессор и память компьютера в фоне, даже
если вы уже не пользуетесь проектом.

### Вариант 1 — закончить работу (без удаления данных)

```bash
docker compose down
```

Контейнеры остановятся, но данные в PostgreSQL (пользователи, проекты, задачи и т.д.)
сохранятся в отдельном Docker-томе и будут на месте при следующем `docker compose up`.

### Вариант 2 — сбросить данные и продолжить работу

Это не про окончание работы, а про то, чтобы вернуть проект в исходное состояние прямо
сейчас и сразу продолжить — поэтому команда заканчивается на `up`, а не на `down`: старые
контейнеры с накопленными данными удаляются, и тут же поднимаются новые, чистые.
Используйте, если данные испортились или нужно начать упражнение заново:

```bash
docker compose down -v
docker compose up --build -d
```

Флаг `-v` удаляет том с данными PostgreSQL — при следующем запуске база создастся заново
и заполнится исходными тестовыми данными.

> Есть и более быстрый способ сброса без пересоздания контейнеров — ручка
> `POST /api/v1/admin/reset` (только для роли `ADMIN`, см. Swagger). Если после сброса вы
> уже закончили работать — не забудьте следом выполнить `docker compose down` из
> Варианта 1.

## 14. Если что-то не работает

- Убедитесь, что Docker Desktop запущен (не просто установлен).
- `docker compose ps` — все сервисы должны быть `Up`/`healthy` (Elasticsearch/Kibana
  стартуют дольше остальных — дайте им 1-2 минуты).
- `docker compose logs -f api` — смотрите сообщение об ошибке в логе.
- Порт `8000` или `5432` уже занят другим процессом — освободите порт или обратитесь
  к преподавателю.
- Полный сброс (раздел 10) решает большинство проблем с "испорченным" состоянием.

Если ничего не помогло — сформулируйте проблему и обратитесь к преподавателю: что
делали, какую команду выполнили, что получили в ответ (текст ошибки/лога).

### Windows: если что-то пошло не так на установке

**Прежде всего — cmd или PowerShell?** В Windows есть два разных терминала, и часть
команд ниже работает только в одном из них.

- **Командная строка (cmd.exe)** — заголовок окна «Командная строка», приглашение вида
  `C:\Windows\system32>`.
- **Windows PowerShell** — заголовок окна «Windows PowerShell», приглашение вида
  `PS C:\Windows\system32>` (обратите внимание на `PS` в начале).

Открывать так: `Win` → напечатать «PowerShell» → правой кнопкой по **Windows PowerShell**
в результатах поиска → «Запуск от имени администратора». Если случайно открылась
«Командная строка» — закройте её, команды ниже туда вставлять не нужно.

#### Docker Desktop пишет «нужно установить WSL»

В **PowerShell от администратора**:

```powershell
wsl --update
wsl --install
```

После выполнения — обязательно **перезагрузите компьютер**: компоненты Windows (WSL,
Virtual Machine Platform) активируются только после перезагрузки, без неё следующий шаг
зависнет.

Если `wsl --install` зависает (курсор мигает, ничего не происходит на скачивании
дистрибутива Ubuntu) — обычно дело в загрузке через Microsoft Store. Прервите
(`Ctrl+C`), перезагрузите ПК ещё раз, затем в PowerShell от администратора:

```powershell
wsl --update --web-download
wsl --install -d Ubuntu
```

Флаг `--web-download` качает файлы напрямую, в обход Store — обычно снимает зависание.
Проверить результат:

```powershell
wsl -l -v
```

Должен появиться дистрибутив (например `Ubuntu`) с `VERSION` = `2`. После этого
запустите/перезапустите Docker Desktop — он сам подхватит WSL2.

#### Контейнер api падает сразу после запуска (Exited)

Если `docker compose ps -a` показывает `api` в статусе `Exited`, смотрим логи:

```bash
docker compose logs api
```

На Windows там иногда одна из двух ошибок (обычно у студентов, клонировавших репозиторий
до того, как в него добавили `.gitattributes` с `eol=lf` для `entrypoint.sh`):

| Ошибка в логах | Причина |
|---|---|
| `exec ./entrypoint.sh: no such file or directory` | Git при клонировании на Windows конвертировал переносы строк в `entrypoint.sh` из Unix (`LF`) в Windows (`CRLF`) — первая строка файла (`#!/bin/sh`) стала невалидной для Linux-контейнера. |
| `exec ./entrypoint.sh: exec format error` | То же самое плюс в файл попал BOM (невидимые байты в начале) — типичный побочный эффект команды `Set-Content -Encoding utf8` в Windows PowerShell при попытке починить файл вручную. |

Исправление — в PowerShell, из папки проекта, переписать файл в Unix-переносах строк без BOM:

```powershell
$content = (Get-Content -Raw entrypoint.sh) -replace "`r`n", "`n"
[System.IO.File]::WriteAllText("$PWD\entrypoint.sh", $content, (New-Object System.Text.UTF8Encoding $false))
```

Затем пересобрать:

```bash
docker compose up --build -d
```
