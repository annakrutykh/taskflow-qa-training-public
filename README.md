# TaskFlow — учебная площадка для QA Engineer (ветка `web`, API + веб-клиент)

Система управления проектами и задачами (упрощённый аналог Jira). Используется как рабочая
среда курса подготовки QA-инженеров: реальный backend (REST API, PostgreSQL) плюс рабочий
веб-интерфейс поверх него — тестировать нужно так же, как в настоящей компании.

> **Это расширенный трек — API + веб-интерфейс.** Если вам нужен только API (тестирование
> через Swagger/Postman, без браузерного интерфейса) — переключитесь на ветку `main`:
> `git checkout main` (после клонирования, раздел 3 ниже).

Эта инструкция рассчитана на то, что вы **никогда раньше не работали с Docker** — читайте
по порядку, ничего не пропускайте.

**Если вы в России — для скачивания PyCharm с jetbrains.com нужен VPN**, сайт не
открывается напрямую (Docker/Git/DBeaver это не касается — их сайты доступны без VPN).

После установки Docker Desktop **запустите его и дождитесь**, пока иконка кита в трее/меню
не покажет, что Docker работает (запущен движок). Все команды `docker compose ...` ниже
работают только при запущенном Docker Desktop.

**На macOS Git отдельно ставить обычно не нужно.** При первом запуске команды `git` в
Терминале система сама предложит установить **Command Line Tools** — соглашайтесь,
установка займёт пару минут, отдельно с git-scm.com ничего скачивать не придётся. Если
Git уже был установлен раньше (например, вместе с Xcode) — команда просто сработает,
никакого попапа не будет. На **Windows** так не работает — Git туда не встроен, нужен
установщик по ссылке из таблицы выше.

Проверить, что Docker и Git установлены, можно в терминале (macOS — приложение
"Терминал", Windows — PowerShell):

```bash
docker --version
git --version
```

Если обе команды выводят номер версии, а не ошибку "command not found" — всё готово.

## 2. Клонирование проекта

```bash
git clone https://github.com/annakrutykh/taskflow-qa-training-public.git
cd taskflow-qa-training-public
```

Репозиторий публичный — аккаунт на GitHub для клонирования не нужен.

### Если не получается через терминал — клонирование через PyCharm

Тот же git clone, но кнопками, без единой команды в терминале:

1. Откройте PyCharm. На стартовом экране — кнопка **Get from VCS** (если
   уже открыт какой-то проект — **File → New → Project from Version
   Control**).
2. В поле **URL** вставьте `https://github.com/annakrutykh/taskflow-qa-training-public.git`.
3. Выберите папку, куда клонировать, и нажмите **Clone**.

Логиниться через GitHub-аккаунт не нужно — репозиторий публичный, PyCharm
скачает его напрямую по ссылке. Единственное условие — Git должен быть
уже установлен (раздел 1 выше), PyCharm сама его найдёт и никакой
дополнительной привязки не потребует.

> Как получать обновления от преподавателя и куда отправлять найденные
> дефекты — `docs/STUDENT_GIT_WORKFLOW.md`.

## 3. Переключение на учебную ветку

В репозитории два трека, оба в одном и том же коде:

| Ветка | Что внутри |
|---|---|
| `main` | Только API — тестирование через Swagger/Postman/curl |
| `web` | Тот же API + рабочий веб-клиент (браузерный интерфейс) |

После `git clone` вы попадаете на `main`. Чтобы переключиться на `web` (эта инструкция —
уже для неё):

```bash
git checkout web
```

Обратно на API-only:

```bash
git checkout main
```

При переключении между ветками контейнеры стоит пересобрать заново — в другой ветке
меняется набор сервисов (появляется/пропадает `web`):

```bash
docker compose down -v
docker compose up --build -d
```

Проверить текущую ветку:

```bash
git branch
```
(активная ветка отмечена звёздочкой `*`)

> Подробнее про работу с git в рамках курса — `docs/STUDENT_GIT_WORKFLOW.md`.

## 5. Запуск проекта

В корневой папке проекта выполните:

```bash
docker compose up --build
```

Первый запуск может занять несколько минут — скачиваются образы PostgreSQL и Python,
собирается образ приложения. В терминале будет много строк лога, это нормально.

При первом запуске автоматически:
- поднимается PostgreSQL;
- накатываются миграции схемы БД (создаются таблицы);
- база данных заполняется тестовыми данными.

Дождитесь строки вида `Application startup complete` и/или `Uvicorn running on
http://0.0.0.0:8000` — это значит, что API готово принимать запросы. Терминал в этом
режиме остаётся "занятым" — это ожидаемо, лог пишется в реальном времени, работу
продолжайте в новом окне терминала.

Если хотите, чтобы контейнеры работали в фоне и не занимали терминал:

```bash
docker compose up --build -d
```

## 6. Как проверить, что контейнеры поднялись

```bash
docker compose ps
```

Все сервисы (`api`, `web`, `db`, `redis`, `redis-commander`, `elasticsearch`, `kibana`) должны
быть в статусе `Up` (или `running`/`healthy`). `elasticsearch`/`kibana` стартуют дольше
остальных — дайте им 1-2 минуты после запуска. Если что-то из них в статусе
`Exit`/`Restarting` — смотрите логи:

```bash
docker compose logs -f api
docker compose logs -f web
```

(`Ctrl+C` — выйти из просмотра логов, сами контейнеры при этом не остановятся).

Быстрая проверка, что API действительно отвечает:

```bash
curl http://localhost:8000/health
```

Ожидаемый ответ — JSON со статусом `ok` (или аналогичным) и кодом `200`.

Веб-интерфейс — откройте в браузере:

```
http://localhost:3000
```

Тестовые учётные записи для входа — раздел 9 ниже. Что тестировать в интерфейсе и как
устроены роли/права — `docs/WEB_SPEC.md`. С чего начать тестирование и по каким этапам
двигаться — `docs/STUDENT_WEB_ASSIGNMENTS.md`. Кликабельные макеты экранов и
дизайн-система: https://annakrutykh.github.io/taskflow-qa-training-public/

## 7. Swagger UI — интерактивная документация API

Откройте в браузере:

```
http://localhost:8000/docs
```

Здесь можно посмотреть все ручки API, их параметры и коды ответов, а также отправлять
запросы прямо из браузера ("Try it out"). Дополнительно доступна raw-схема:

```
http://localhost:8000/openapi.json
```

### Kibana и Redis — необязательные инструменты

**Все инструменты в этом разделе не обязательны** — весь курс можно пройти
через Swagger, Postman и PostgreSQL. Ниже — как подключиться, если хотите
попробовать; учебные задания по каждому — в `docs/STUDENT_LOG_ANALYSIS.md`.

#### Kibana (поиск по логам)

```
http://localhost:5601
```

Пошагово:

1. Сначала сделайте хотя бы пару запросов к API (например, откройте
   Swagger — `http://localhost:8000/docs` — и вызовите любую ручку, или
   просто полистайте веб-интерфейс/приложение). Логи в Elasticsearch
   появляются только после реальных запросов — до этого индекса
   `taskflow-logs-*` попросту не существует.
2. Откройте ссылку выше — логин/пароль вводить не нужно, авторизация в
   Kibana отключена.
3. Слева откройте меню (☰) → **Discover**.
4. При первом заходе Kibana попросит создать **Data View**. В форме два
   разных поля, не перепутайте:
   - **Name** — произвольное название для себя, на поиск не влияет
     (например, просто `taskflow-logs`).
   - **Index pattern** — сюда вводите именно `taskflow-logs-*`, **со
     звёздочкой на конце** (это wildcard: без неё Kibana не найдёт индексы,
     в имени которых зашита дата).
5. **Timestamp field** — выберите `@timestamp`.
6. Нажмите **Save data view to Kibana** (или **Create data view**).

> Если вместо формы создания Data View видите экран «Welcome to
> Analytics!» с кнопкой «Add integrations» — это не баг, а признак того,
> что логов ещё нет (шаг 1 выше). Сделайте несколько запросов к API и
> обновите страницу (`F5`) — тогда Kibana предложит создать Data View как
> положено.

#### Redis Commander (просмотр ключей Redis в браузере)

```
http://localhost:8081
```

Пошагово:

1. Откройте ссылку выше.
2. Ничего вводить не нужно — подключение к Redis уже настроено в
   `docker-compose.yml`, слева сразу видно дерево ключей (пустое, пока не
   сгенерируете активность через API).

## 8. Подключение к PostgreSQL через DBeaver

Параметры подключения:

| Параметр | Значение |
|---|---|
| Host | localhost |
| Port | 5432 |
| Database | taskflow |
| Username | taskflow |
| Password | taskflow |

Пошагово:

1. Откройте DBeaver.
2. **File → New → Database Connection** (или кнопка "New Database Connection" на панели).
3. Выберите **PostgreSQL** → Next.
4. Заполните поля Host/Port/Database/Username/Password из таблицы выше.
5. Нажмите **Test Connection...** — если DBeaver попросит скачать драйвер PostgreSQL,
   согласитесь (Download).
6. После успешной проверки ("Connected") нажмите **Finish**.

После подключения в дереве слева будут доступны таблицы: `users`, `projects`, `tasks`,
`project_members`, `comments`, `labels`, `task_labels`, `audit_log`.

| Роль | Email | Пароль |
|---|---|---|
| ADMIN | admin@example.com | Admin123! |

## 10. Запуск после перезагрузки компьютера

Docker Desktop нужно запустить заново (если не настроен автозапуск) и дождаться его
готовности. После этого в папке проекта:

```bash
docker compose up -d
```

(без `--build` — образ уже собран, пересобирать заново не нужно, если вы не меняли код).
Все данные в PostgreSQL сохраняются между перезапусками, если вы не выполняли
`docker compose down -v`.

## 11. Остановка контейнеров

Остановить приложение **без удаления данных**:

```bash
docker compose down
```

Контейнеры остановятся, но данные в PostgreSQL (пользователи, проекты, задачи и т.д.)
сохранятся в отдельном Docker-томе и будут на месте при следующем `docker compose up`.

### Полный сброс базы данных

Если нужно вернуть проект в исходное состояние (например, данные испортились или нужно
начать упражнение заново):

```bash
docker compose down -v
docker compose up --build
```

Флаг `-v` удаляет том с данными PostgreSQL — при следующем запуске база создастся заново
и заполнится исходными тестовыми данными.

> Есть и более быстрый способ сброса без пересоздания контейнеров — ручка
> `POST /api/v1/admin/reset` (только для роли `ADMIN`, см. Swagger).

## 12. Часто используемые команды

```bash
# Запустить (в фоне)
docker compose up -d

# Запустить с пересборкой образа (после git pull с изменениями в коде)
docker compose up --build -d

# Посмотреть статус контейнеров
docker compose ps

# Посмотреть логи API в реальном времени
docker compose logs -f api

# Зайти в консоль базы данных из терминала (альтернатива DBeaver)
docker compose exec db psql -U taskflow -d taskflow

# Остановить, данные сохранить
docker compose down

# Остановить и удалить все данные (полный сброс)
docker compose down -v
```

## 14. Автотесты (внутренняя инфраструктура, не часть курса)

В репозитории есть `pytest`/`Makefile`/CI — это защита самого проекта от регрессий,
не учебный материал. **Вам не нужно их писать или запускать** — весь курс проходится
через Swagger/Postman/PostgreSQL/Kibana. В проекте действительно есть автотесты —
если куратор или автотестер попросит вас их прогнать, он даст конкретную команду;
короткая справка, что она делает, — `docs/TESTING.md`.

### Postman

Коллекция со всеми ручками — `postman/TaskFlow.postman_collection.json`. Импортируйте
файл в Postman: переменная `baseUrl` уже указывает на `http://localhost:8000`,
`accessToken`/`adminAccessToken` заполняются автоматически после запросов логина.

## 15. Если что-то не работает

- Убедитесь, что Docker Desktop запущен (не просто установлен).
- `docker compose ps` — все сервисы должны быть `Up`/`healthy` (Elasticsearch/Kibana
  стартуют дольше остальных — дайте им 1-2 минуты).
- `docker compose logs -f api` — смотрите сообщение об ошибке в логе.
- Порт `8000` или `5432` уже занят другим процессом — освободите порт или обратитесь
  к преподавателю.
- Полный сброс (раздел 11) решает большинство проблем с "испорченным" состоянием.

Если ничего не помогло — сформулируйте проблему и обратитесь к преподавателю: что
делали, какую команду выполнили, что получили в ответ (текст ошибки/лога).
